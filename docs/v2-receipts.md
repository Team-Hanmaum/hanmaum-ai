# v2 수신 기록과 중복 호출 차단

v2의 stub과 OpenAI 제공자는 같은 중복 차단 경로를 사용한다. 수신 기록은 분석 결과 캐시와 별도로 관리한다. [로컬 설정](../README.md#v2-http-실행) · [외부 계약](ai-contract-v2.md) · [운영 배포](deployment.md)

## 저장소와 키

- 로컬과 Lightsail에서 AI 전용 SQLite 파일을 사용한다. 같은 호스트의 신뢰할 수 있는 파일시스템에서 같은 파일을 공유하는 프로세스가 지원 범위다. 다중 호스트·네트워크 드라이브는 별도 저장소 어댑터가 필요하다.
- `(contract_version, request_id)`가 기본 키다. 정규화 규칙 버전·HMAC 키 버전·32바이트 HMAC-SHA256만 함께 저장한다. 원문·제안·인증키는 저장하지 않는다.
- `BEGIN IMMEDIATE` 안에서 기존 행을 확인하고 등록하며 커밋 성공 뒤 호출을 허용한다. 연결은 `synchronous=FULL`을 적용하고 `OFF`·`MEMORY` journal을 거부한다.
- 상위 디렉터리를 준비하고 `uv run --locked python -m app.v2.initialize_receipts <절대경로>`로 최초 한 번 초기화한다. 실행 중에는 기존 파일을 `mode=rw`로 연다. 파일 유실·손상·스키마 불일치는 저장소 장애로 처리한다.
- 기존 기록은 저장된 규칙·키 버전으로 비교한다. 같은 버전명으로 키를 교체하거나 해당 기록에 필요한 키와 규칙을 제거하면 비교할 수 없다. 운영 재배포는 기존 키 구성을 보존한다. 보관 기간·정리 후 중복 차단 범위와 키 교체 절차는 별도 결정한다.

## 동일 본문 판정

객체 키 순서·JSON 이스케이프 차이와 선언된 UUID 필드의 대소문자는 동일하게 처리한다. `recordedAt`은 같은 UTC 시점으로 비교하며 소수초 6자리로 고정한다. 범위 경계는 날짜·시간 산술로 처리한다. 배열 순서, 텍스트 공백·줄바꿈·유니코드, `DIRECT_INPUT.text` 내부 JSON 표현은 그대로 비교한다. 자세한 규칙은 [v2 계약 11절](ai-contract-v2.md#11-동일-본문-판정)을 따른다.

## 처리 순서와 오류

1. 인증, 진입 슬롯 확보, 제한된 본문 수신 및 요청 검증 후 불변 스냅샷을 만든다.
2. 제공자 설정을 확인한 뒤 기존 기록을 조회한다. 기존 기록 판정이 제공자 슬롯 포화보다 우선한다.
3. 신규 요청은 슬롯을 확보하고 원자적 등록에서 재확인한다. 최초 등록 승자만 제공자를 호출한다.
4. 같은 스냅샷으로 응답을 검증하고 직렬화 상한을 확인한다. 위반이 하나라도 있으면 전체 결과를 거부한다.

| 조건 | 결과 | 해당 요청의 제공자 호출 |
| --- | --- | --- |
| 같은 ID·같은 본문 | `409 REQUEST_ALREADY_RECEIVED` | 0회 |
| 같은 ID·다른 본문 | `409 REQUEST_ID_REUSED` | 0회 |
| 저장소 조회·등록·커밋 실패 또는 불확실 | `503 RECEIPT_STORE_UNAVAILABLE` | 0회 |
| 기존 기록 비교 불가 | `503 REQUEST_COMPARISON_UNAVAILABLE` | 0회 |
| 진입·저장소 제출·제공자 슬롯 포화 | `503 AI_OVERLOADED` | 0회 |

등록 뒤 제공자 오류·타임아웃·연결 단절·과대 결과가 생겨도 기록을 보존한다. 등록 워커가 취소 뒤 커밋해도 워커는 제공자를 호출하지 않는다. 재요청 시 새 실행이 필요하면 새 ID를 사용한다.

지원 구성은 프로세스당 ASGI 앱 하나다. 진입 4개·제공자 2개·CPU 및 저장소 작업 각각 4개에 대기열을 두지 않는다. 기본 전체 처리 26초와 응답 전송 0.5초 안에서 각 작업의 예산을 제한한다. 제공자 기본 대기는 20초·최대 25초다. 기한이 지나면 늦은 결과를 반환하지 않고 작업 종료까지 슬롯을 유지한다. 제공자 처리·과금 중단은 보장하지 않는다.

## 진단과 검증

진단은 고정 실패 분류만 로그와 프로세스별 메모리 카운터에 기록한다. 원문·제안·요청 ID·키·DB 경로·예외 원문은 기록하지 않는다.

```sh
uv run --locked pytest tests/test_v2_receipts.py tests/test_v2_receipt_regressions.py tests/test_v2_http.py
uv run --locked python scripts/fixture_manifest.py
```

테스트는 SQLite 경쟁·재시작, 키/규칙 오류, DB 장애, 타임아웃 뒤 기록·슬롯 보존, 민감 정보 비노출을 확인한다. 모델 품질 평가는 [별도 합성 평가 절차](v2-integration.md#6-합성-데이터로-모델-품질-재평가)를 따른다.
